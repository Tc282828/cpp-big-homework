# 一、作业题目

格温小姐大冒险。

本项目是一个使用 C++ 和 EasyX 图形库完成的 2D 躲避类小游戏。玩家控制角色在中路河道地图中移动，躲避不断出现的敌方技能，并通过 J 键释放防御迷雾来短时间免疫伤害。

项目包含开始界面、游戏界面、结束界面、玩家移动、敌方技能生成、碰撞检测、血量系统、分数系统、防御技能和音效系统等内容。

# 四、主要流程

## 1. 整体流程

游戏整体运行流程如下：

```text
程序启动
    ↓
初始化窗口和资源
    ↓
显示开始界面
    ↓
按 Enter 开始游戏
    ↓
进入游戏主循环
    ↓
读取玩家输入
    ↓
更新玩家位置和技能状态
    ↓
生成敌方技能
    ↓
检测玩家与技能是否碰撞
    ↓
更新血量、时间、分数和防御状态
    ↓
绘制地图、技能、玩家和 UI
    ↓
判断胜利或失败
    ↓
进入结束界面
    ↓
按 R 重新开始或按 ESC 退出
```

游戏主循环可以概括为：

```text
输入处理 → 数据更新 → 碰撞检测 → 画面绘制 → 下一帧
```

程序通过循环不断刷新游戏画面，并使用 `Sleep(16)` 控制每帧之间的间隔，使游戏接近 60 FPS。

## 3. 类设计

### 3.1 Game 类

Game 类负责整个游戏流程控制，是项目中最核心的控制类。

主要功能包括：

```text
创建 EasyX 窗口
加载图片资源
加载音效资源
处理键盘输入
更新游戏数据
生成敌方技能
判断碰撞
绘制游戏画面
判断胜利或失败
```

Game 类中包含玩家对象和技能数组：

```cpp
Player player;
std::vector<Skill> skills;
```

其中，`player` 表示当前玩家角色，`skills` 保存当前画面中所有仍然有效的敌方技能。

Game 类还维护游戏状态：

```cpp
enum GameState
{
    MENU,
    PLAYING,
    WIN,
    GAME_OVER
};
```

不同状态对应不同界面：

| 状态 | 含义 |
|---|---|
| MENU | 开始界面 |
| PLAYING | 游戏进行中 |
| WIN | 胜利界面 |
| GAME_OVER | 失败界面 |

---

### 3.2 Player 类

Player 类表示玩家角色。

主要成员变量包括：

```text
x, y：玩家当前位置
speed：移动速度
radius：碰撞半径
hp：生命值
invincibleTimer：受伤后的无敌时间
defenseTimer：防御迷雾剩余时间
defenseCooldown：防御迷雾冷却时间
usingDefense：当前是否处于防御状态
```

Player 类主要负责：

```text
处理玩家移动
限制玩家不走出边界
处理玩家受伤
处理 J 键防御技能

```

### 3.3 Skill 类

Skill 类表示敌方技能。

项目中设计了三种技能：

| 技能类型 | 说明 |
|---|---|
| EZ_Q | 快速直线飞行技能 |
| ASHE_R | 较大范围直线飞行技能 |
| LUX_E | 范围预警爆炸技能 |

Skill 类主要成员变量包括：


飞行技能会根据玩家位置计算飞行方向，使技能可以斜向移动。

## 4. 核心功能实现

### 4.1 游戏循环

游戏主循环是整个程序持续运行的基础。

基本流程如下：

```cpp
while (running)
{
    handleInput();
    update();
    draw();
    FlushBatchDraw();
    Sleep(16);
}
```

其中：

| 函数 | 作用 |
|---|---|
| handleInput() | 处理键盘输入 |
| update() | 更新玩家、技能、分数和状态 |
| draw() | 绘制当前游戏画面 |
| FlushBatchDraw() | 将缓冲区画面刷新到窗口 |
| Sleep(16) | 控制刷新速度 |

---

### 4.2 玩家移动

玩家可以使用 WASD 或方向键移动。

移动方式如下：

```text
W / ↑：向上移动
S / ↓：向下移动
A / ←：向左移动
D / →：向右移动
```

移动时会修改玩家坐标：

```text
向上移动：y 减小
向下移动：y 增大
向左移动：x 减小
向右移动：x 增大
```

为了防止玩家走出窗口，程序会在移动后进行边界检查。

边界检查思路如下：

```text
如果 x 小于左边界，则 x 等于左边界
如果 x 大于右边界，则 x 等于右边界
如果 y 小于上边界，则 y 等于上边界
如果 y 大于下边界，则 y 等于下边界
```

---

### 4.3 技能生成

游戏会随机生成敌方技能。

飞行类技能会生成一条穿过玩家附近的长直线弹道。

```text
随机选择一个方向
从屏幕外一侧飞入
穿过玩家附近区域
从屏幕外另一侧飞出
```

生成后，技能会沿着这条弹道持续飞行。

这样可以避免技能路线太单一，也让飞行方向和技能图片朝向更一致。

---

### 4.4 技能方向计算

技能生成后，需要沿着生成好的弹道方向移动。

核心计算过程如下：

```text
dx = 目标点x - 技能x
dy = 目标点y - 技能y
距离 = sqrt(dx * dx + dy * dy)
vx = dx / 距离 * 速度
vy = dy / 距离 * 速度
```

其中：

| 变量 | 含义 |
|---|---|
| dx | 横向距离 |
| dy | 纵向距离 |
| 距离 | 技能到玩家的直线距离 |
| vx | 技能每帧横向移动距离 |
| vy | 技能每帧纵向移动距离 |

通过这种方式，技能可以沿着穿过玩家附近的长直线弹道飞行。

---

### 4.5 碰撞检测

本项目主要使用两种碰撞检测方式。

矩形与圆形碰撞用于飞行类技能：

```text
EZ_Q
ASHE_R
```

圆形与圆形碰撞用于范围类技能：

```text
LUX_E
```

玩家使用圆形碰撞范围，技能根据类型使用矩形或圆形范围。

如果检测到碰撞，且玩家没有处于防御或无敌状态，则玩家扣血。

---

### 4.6 受伤与无敌状态

玩家被技能命中后会扣除 1 点生命值，并进入短暂无敌状态。

无敌状态的作用是避免玩家在短时间内被同一个技能或多个技能连续扣血。

逻辑如下：

```text
玩家被击中
    ↓
如果没有无敌，也没有防御
    ↓
生命值减 1
    ↓
进入短暂无敌时间
```

---

### 4.7 J 键防御迷雾

玩家按 J 可以释放防御迷雾。

防御迷雾的规则如下：

```text
持续时间：约 1 秒
冷却时间：约 5 秒
防御期间：玩家不会受到敌方技能伤害
显示效果：玩家周围出现蓝色防御迷雾
```

防御技能的基本逻辑如下：

```text
按下 J
    ↓
判断是否处于冷却
    ↓
如果不在冷却中，进入防御状态
    ↓
显示防御迷雾
    ↓
防御时间结束
    ↓
进入冷却
```

防御期间的碰撞处理如下：

```text
如果玩家处于防御状态
    不扣血
否则
    正常扣血
```

这样既有画面表现，也能真正影响游戏逻辑。

### 4.8 音效系统

项目使用 Windows 的 PlaySound 播放 wav 音效。

代码中引入：

```cpp
#include <mmsystem.h>
#pragma comment(lib, "winmm.lib")
```

音效播放函数大致如下：

```cpp
PlaySound(soundPath, NULL, SND_FILENAME | SND_ASYNC);
```

其中：

| 参数 | 含义 |
|---|---|
| soundPath | 音效文件路径 |
| SND_FILENAME | 表示从文件播放音效 |
| SND_ASYNC | 异步播放，避免游戏卡住 |

当前音效触发时机如下：

| 音效 | 触发时机 |
|---|---|
| 我觉得ok.wav | 按 Enter 开始游戏 |
| 啊！！惨叫.wav | 玩家真正扣血 |
| gwen_W.wav | J 防御成功释放 |
| lux.wav | 光辉 E 预警音效 |
| 超级玛丽死亡音效.wav | 玩家血量归零 |

为了防止死亡音效重复播放，程序设置了状态标记，使失败音效只在进入 GAME_OVER 时播放一次。

## 运行提示

从 GitHub 下载项目后，请使用 Visual Studio 打开 `GwenDodgeGame.vcxproj` 运行项目，不要直接运行单个 `Game.cpp` 文件。

如果仍然提示“图片资源加载失败，请检查 assets 文件夹”，请检查是否移动了 `assets` 文件夹，或者是否没有先用 Visual Studio 编译项目。

# 六、开发过程中遇到的问题与解决方法

## 1. PNG 图片透明背景问题

问题：

部分 PNG 图片直接显示时可能出现黑底。

解决方法：

使用透明贴图绘制函数，使角色、技能和 UI 图片能够保留透明背景。

收获：

图形化程序不仅需要加载图片，还需要考虑图片的透明通道，否则画面会很不自然。

---

## 2. 技能只能水平飞行的问题

问题：

早期技能只从右向左飞，画面比较单调。

解决方法：

根据玩家当前位置计算技能方向，使技能可以从不同边缘生成并朝玩家方向飞行。

收获：

通过向量计算可以实现更自然的运动方向。

---

## 3. 玩家连续扣血问题

问题：

如果玩家停留在技能范围内，可能会连续多次扣血。

解决方法：

给玩家增加受伤后的无敌时间。

收获：

游戏中的受击逻辑不能只考虑碰撞，还需要考虑玩家体验。

---

## 4. J 防御只显示图片但没有免伤的问题

问题：

防御技能最初只是在画面上显示迷雾，如果没有修改碰撞逻辑，玩家仍然会扣血。

解决方法：

在碰撞处理时判断玩家是否处于防御状态，如果处于防御状态，则不扣血。

收获：

技能效果需要同时体现在画面表现和实际逻辑中。

---

## 5. 音效重复播放问题

问题：

如果在失败界面每一帧都播放死亡音效，会导致声音重复。

解决方法：

增加状态变量，使死亡音效只在第一次进入失败状态时播放。

收获：

游戏状态切换时的事件要和每帧刷新区分开。

---

## 6. GitHub 仓库文件混乱问题

问题：

早期提交时把 `.vs`、`bin`、`obj` 等本地编译文件也上传到了仓库。

解决方法：

添加 `.gitignore`，并删除不需要上传的编译产物。

收获：

GitHub 仓库应该主要保存源码、资源和说明文档，不应该上传本地缓存和编译结果。

# 七、AI 使用说明

本项目开发过程中使用了 ChatGPT / Codex 进行辅助，主要用于解决一些实现难点和整理文档。项目代码经过本人理解、修改、运行和调试后整合到最终版本中。

| 使用位置 | AI 具体用途 |
|---|---|
| 图片素材 | 项目中的封面、结束页、角色和部分技能图片由 GPT 辅助生成 |
| PNG 透明显示 | 辅助分析 EasyX 显示 PNG 时出现黑底、白边、棋盘格背景的问题 |
| 技能旋转显示 | 辅助修改飞行技能旋转后出现灰色虚线框、方向不明显的问题 |
| 右键移动 | 辅助设计右键点击目标点后自动移动的向量计算方式 |
| 技能弹道 | 辅助调整 EZ Q 和寒冰 R 的长直线飞行弹道 |

其中比较困难的是 PNG 透明处理和旋转技能贴图。部分素材不是真正透明背景，而是带有白底或灰白棋盘格，直接 `putimage` 会出现黑底或白边。参考 AI 的思路后，代码里没有继续使用普通占位图，而是手动判断哪些像素应该跳过。

例如，真正透明的像素直接不绘制：

```cpp
if (useAlpha && alpha == 0)
{
    continue;
}
```

对于旋转后的技能图片，EasyX 有时会留下黑色或灰色边缘，所以又增加了背景色判断：

```cpp
if (cleanRotateBack && red < 8 && green < 8 && blue < 8)
{
    return true;
}

if (cleanRotateBack && isGrayLike && red < 170 && green < 170 && blue < 170)
{
    return true;
}
```

这部分代码主要解决了技能图片旋转后出现黑边、白边和灰色虚线框的问题。AI 在这里主要提供了排查方向和代码思路，最终代码经过本人运行游戏、观察画面、修改阈值后整合完成。

# 八、收获

本次大作业最大的收获是把课堂中的 C++ 基础语法放进了一个完整的小项目里。游戏不是只写一个 `main.cpp` 就结束，而是需要把玩家、技能、碰撞、资源和游戏流程拆开管理，这样后面增加防御、音效和右键移动时，代码不会全部混在一起。

在玩家移动部分，项目加入了右键点击移动。通过计算当前位置到目标点的方向，再按速度逐帧移动，理解了简单向量计算在游戏中的作用。

```cpp
float distanceX = targetX - x;
float distanceY = targetY - y;
float distance = sqrt(distanceX * distanceX + distanceY * distanceY);

x += distanceX / distance * speed;
y += distanceY / distance * speed;
```

在技能和碰撞部分，项目根据不同技能选择不同的碰撞方式。飞行技能用矩形和玩家圆形检测，光辉 E 用圆形范围检测，这让我理解到游戏规则需要落实到具体判断代码里。

```cpp
if (skills[i].getType() == LUX_E)
{
    isHit = circleCollide(skills[i].getX(), skills[i].getY(), (float)skills[i].getRadius(),
        player.getX(), player.getY(), (float)player.getRadius());
}
else
{
    isHit = rectCircleCollide(skills[i].getRect(), player.getX(), player.getY(), (float)player.getRadius());
}
```

J 防御技能让我学会了用计时器控制技能状态。只有冷却结束并且当前没有防御时才能释放，防御成功后再播放音效，这样可以避免冷却中反复触发。

```cpp
if (defenseCooldown <= 0 && defenseTimer <= 0)
{
    defenseTimer = DEFENSE_KEEP_FRAME;
    defenseCooldown = DEFENSE_COOLDOWN_FRAME;
    usingDefense = true;
    playSoundEffect(_T("assets/sounds/gwen_W.wav"));
}
```

音效部分也带来了一些收获。音效不能随便每帧播放，而应该绑定在具体事件上，例如光辉 E 预警圈出现时播放提示音效，死亡音效只在进入失败状态时播放一次。

```cpp
skills.push_back(Skill::createLuxE(luxX, luxY));
playSoundEffect(_T("assets/sounds/lux.wav"));
```

通过这个项目，C++ 的类、函数、条件判断、循环、数学计算和文件组织都得到了实际练习。同时，项目按 v1.0 到 v6.0 逐步迭代，也让我体会到版本管理和阶段性提交的重要性。
